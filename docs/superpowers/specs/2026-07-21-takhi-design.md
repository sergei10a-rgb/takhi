# Тахь (takhi) — дизайны спек

**Огноо:** 2026-07-21 · **Төлөв:** хянуулахаар · **Хэлэлцүүлэг:** QGO зах зээлийн судалгаа (`C:\claude\_qgo\QGO_SUDALGAA_MN.md`) дээр суурилсан brainstorming

---

## 1. Нэг өгүүлбэрээр

**Тахь** — Nostr дээр суурилсан, эзэнгүй, шимтгэлгүй, нээлттэй эхийн такси-учралын апп: жолооч зорчигч хоёр шууд учирч, өөрсдөө үнээ тохирч, өөрсдөө төлбөрөө шийддэг; голд нь хэн ч байхгүй.

Нэрийн утга: тахь — дэлхийн цорын ганц хэзээ ч гаршуулагдаагүй зэрлэг адуу. Эзэнгүй унаа. «Тахь» ~ «такси», «takhi» ~ «taxi» — хоёр хэлэнд зэрэг эгшиглэнэ.

- **Протокол** (дэлхийд): `takhi` — латин нэр, PROTOCOL.md, хэн ч өөрийн клиент бичиж болно
- **Апп** (Монголд): **Тахь** — кирилл нэр, Flutter клиент

## 2. Зорилго ба амжилтын шалгуур

Гурван шат (дараалал чухал):

| Шат | Зорилго | Амжилтын шалгуур |
|---|---|---|
| **1. PoC** | Концепц ажилладагийг нотлох | 2 бодит утас, нийтийн relay-ээр бүтэн урсгал: дуудлага → санал → тохироо → аялал → хос гарын үсэгтэй баримт. ≥3 нийтийн relay манай event-үүдийг дамжуулдаг нь батлагдсан |
| **2. УБ бодит хэрэглээ** | Өдөр бүр бодит аяллууд | Эхний бодит (танил биш) жолооч-зорчигчийн аялал; гудамжны QR элсүүлэлт ажилладаг нь батлагдсан |
| **3. Хөдөлгөөн** | Нийтийн өмч болох | Гаднын contributor код оруулсан; өөр хот/улс fork хийсэн; зохиогчоос хамааралгүй амьдардаг |

**Unicorn-зорилго** (хоёр утгаар, хоёулаа):
- **Нөлөө:** Монголын зах зээлийг үнэгүйгээрээ эзэлж, дэлхийд fork-логдох протокол
- **Чанар:** дэлхийн түвшний UX/craft — хүмүүс өөрсдөө сурталчилдаг апп (§10)

## 3. Эвдэшгүй зарчмууд (invariants)

1. **Оператор байхгүй.** Зохиогч relay ажиллуулахгүй — апп нийтийн relay-үүд ашиглана. Зохиогч = зөвхөн код бичигч.
2. **Мөнгө апп дундуур урсдаггүй.** Бэлэн эсвэл банкны QR — хоёр хүний хооронд шууд.
3. **Шимтгэл, subscription, төлбөртэй давхарга байхгүй.** Хэзээ ч.
4. **Identity = түлхүүр.** Сервер дээр данс, бүртгэл, утасны дугаар байхгүй. (Утасны дугаар identity биш — гэхдээ тохирсон хоёр тал хоорондоо сайн дураар, шифрлэгдсэн сувгаар солилцож болно, §7.3.)
5. **Хэн ч устгаж чадахгүй.** Сүлжээ зөвхөн бүх хэрэглэгч ажиллуулахаа болиход үхнэ.
6. **Цэвэр нээлттэй эх.** AGPL-3.0, CLA байхгүй, компани-гарц байхгүй (санаатайгаар орхисон — хэлэлцүүлгээр шийдсэн).

## 5. Архитектур

```
┌─────────────────────────────────────────┐
│  Тахь апп (Flutter, нэг апп хоёр горим) │
│  зорчигч ⇄ жолооч                       │
└───────────────┬─────────────────────────┘
                │ Dart Nostr сан (NIP-01/06/13/17/40/44)
                ▼
┌─────────────────────────────────────────┐
│  Олон нийтийн Nostr relay-үүд (3-5)     │
│  жагсаалт хэрэглэгчид засварлагдана      │
└─────────────────────────────────────────┘
```

- Зохиогчийн сервер **байхгүй**. Relay = «тэнэг дамжуулагч», солигдоно, хэн ч нэмж болно.
- Бүх event гарын үсэгтэй; хувийн мэдээлэл болгон шифрлэгдсэн.
- Дуудлагын тархалт: geohash шошгоор — жолооч өөрийн орчмын geohash-уудад бүртгүүлж сонсоно.
- Default relay жагсаалт аппад суулгагдсан (тогтвортой, ephemeral event нэвтрүүлдэг, PoW хүлээдэг нь PoC-оор баталгаажна); тохиргоонд нэмэх/хасах чөлөөтэй.

## 6. Дата загвар (takhi протоколын event-үүд)

Kind дугаарууд — **саналын түвшинд**, эцсийн дугаар PROTOCOL.md v0.1-д тогтоно.

| Юу | Kind (санал) | Төрөл | Агуулга |
|---|---|---|---|
| Профайл | 0 + `takhi` өргөтгөл | replaceable | нэр, горим; жолоочийнх: машин, өнгө, улсын дугаар, км-тариф. **Банкны QR ОРОХГҮЙ** (§8) |
| Дуудлага | 20177 | ephemeral + NIP-40 expiry | суух орчмын **geohash-6** (~±600м), очих geohash-6, санал үнэ (заавал биш), тэмдэглэл, NIP-13 PoW |
| Санал / тохиролцоо | NIP-17 шифрлэгдсэн DM | private | үнэ / эсрэг үнэ, машин, ETA, жолоочийн npub (нэр хүнд харах) |
| Тохироо + яг байршил | NIP-17 DM | private | зорчигч СОНГОСОН жолоочид л: яг цэг (Plus Code + координат) + чөлөөт текст landmark |
| Аяллын амьд байршил | 20178 | ephemeral, NIP-44 шифртэй, p-tag хүлээн авагч | 5-10 сек тутам, зөвхөн хоёулхны хооронд |
| **Аяллын баримт** | 30177 | addressable, `d`=trip_id | нөгөө талын npub, үүрэг (жолооч/зорчигч), зай, хугацаа, үнэ (₮), үнэлгээ 1-5, сэтгэгдэл |
| Чат зурвас | NIP-17 DM | private | тохирсон хоёулхны хооронд: текст + бэлэн хариултууд («Гарлаа», «Орцны урд байна») |
| Дуудлагын signaling | NIP-17 DM | private | WebRTC offer/answer/ICE — P2P дуут ярианы холболт тогтоох (§7.3) |
| Туслагч-зарлал | 30178 | addressable | сайн дурын blind relay (TURN) зангилааны хаяг/credential — хэн ч зарлаж, хэн ч ашиглана (§7.3-①) |
| Дугаар солилцоо | NIP-17 DM (тохироо-DM дотор) | private | сонголттой `phone` талбар — зөвхөн тохирсон нөгөө талдаа (§7.3) |
| Цуцлалт | NIP-17 DM | private | шалтгаан (сонголттой) |
| Блок жагсаалт | NIP-51 mute list | local/private | клиент талын хаалт — төв модератор байхгүйн орлуулга |

**Нууцлалын шаталсан задаргаа** — гол зарчим: нийтэд = бүдүүвч байршил (geohash-6), сонгосон жолоочид = яг цэг, аяллын явцад = зөвхөн хоёулаа. Зорчигчийн яг байршил хэзээ ч нийтэд ил гардаггүй.

## 7. Үндсэн урсгалууд

### 7.1 Дуудлага → аялал (тохиролцсон үнэ)
1. Зорчигч: цэгээ зурж/сонгож, санал үнээ (заавал биш) оруулаад **дуудлага** нийтэлнэ (PoW бодогдоно, 4 мин expiry).
2. Ойролцоох сонсож буй жолооч нарт харагдана (жагсаалт: зай, үнэ, чиглэл).
3. Жолооч санал явуулна: зөвшөөрөх эсвэл эсрэг үнэ. Зорчигч олон саналыг зэрэг харна — **нэр хүнд + үнэ + ETA**-гаар сонгоно.
4. Сонгогдсон жолоочид яг цэг + landmark текст очно. Бусад саналууд expiry-ээрээ унтарна.
5. Жолооч ирэх зам + аяллын туршид: хоёр тал бие биеийн амьд байршлыг харна.
6. Жолооч «Аялал дууслаа» дарна → хоёр тал **баримт** гарын үсэглэнэ (§9) → төлбөр: бэлэн эсвэл жолоочийн дэлгэц дээрх QR-ыг зорчигч банкны аппаараа уншуулна.

### 7.2 GPS таксиметр горим
- Жолоочийн профайлд км-тариф. Аялал «таксиметрээр» гэж тохирвол хоёр утас **тус тусдаа** GPS зайг хэмжинэ.
- Төгсгөлд: дүн = тариф × жолоочийн хэмжсэн зай. Зорчигчийн апп өөрийн хэмжсэн зайг зэрэгцүүлж харуулна (ил тод байдал).
- Зорчигч дүнг баталж гарын үсэглэнэ. Татгалзвал баримт хосгүй үлдэнэ (§9-ийн жингүй).

### 7.3 Холбоо барих (тохироо болсны дараа)

Монголын бодит хэрэглээ: жолооч «ирлээ», зорчигч «хаана байна» гэж ЗАЛГАДАГ. Гурван суваг, дарааллаар:

**① 📞 P2P дуут яриа (үндсэн, MVP-д)** — апп доторх WebRTC дуудлага:
- Signaling = NIP-17 шифрлэгдсэн DM-ээр (offer/answer/ICE candidate) — өөрсдийн relay-үүдээрээ, дуудлагын сервергүй.
- NAT traversal = нийтийн STUN серверүүд (жагсаалт тохиргоонд, солигдоно). STUN нь зөвхөн хаяг-олох stateless үйлчилгээ.
- **Punch бүтэхгүй үед — «туслагч зангилаа» (community blind relay).** Keet/Holepunch-ийн батлагдсан зарчим: гуравдагч зангилаа пакет дамжуулна, гэхдээ медиа DTLS-SRTP шифртэй тул **юу ч сонсож чадахгүй** (blind). Хэрэгжүүлэлт нь стандарт TURN протокол — WebRTC төрөлхийн дэмждэг тул тусгай код бараг хэрэггүй. Гол ялгаа: **зохиогч TURN ажиллуулахгүй** — сайн дурынхан (Nostr relay-тэй яг адил загвараар) асааж, Nostr-оор зарлана (§6 туслагч-зарлал); апп олдсон туслагчдыг ICE тохиргоондоо нэмнэ; жагсаалт хэрэглэгчид засварлагдана. Эхэн үед туслагч байхгүй байж болно — тэр үед ② / дуут зурвас руу унана.
- Бүрэн fallback гинж: **шууд P2P → туслагч зангилаа (олдвол) → ② энгийн залгалт / ③ дуут зурвас** — сүүлийн хоёр нь ямар ч NAT-д ажиллана.
- Яриа хоёр утасны хооронд (эсвэл blind туслагчаар) DTLS-SRTP шифртэй.

**② Энгийн залгалт (fallback)** — дугаар солилцсон бол:
- Тохиргоонд **«Дугаараа тохирсон хүнд илгээх»** toggle (default: асаалттай). Асаалттай бол тохироо-DM дотор дугаар шифрлэгдэн зөвхөн нөгөө талд очно.
- Дугаар зөвхөн локал хадгалагдана. (Шударга тэмдэглэл: нөгөө хүн дугаарыг чинь хадгалж чадна — toggle унтраавал ①/③ л үлдэнэ.)

**③ 💬 Чат + дуут зурвас** — NIP-17, үргэлж бэлэн: текст + бэлэн хариултууд («Гарлаа», «Орцны урд байна», «2 минут») + **богино дуут зурвас** (≤10 сек, opus ~30KB, DM дотор) — жижиг тул Nostr relay-ээр шууд явна, ямар ч NAT-д 100% хүрнэ.

### 7.4 Таксиметр — гар өргөсөн зорчигч (Замын Унаа горим)

Гудамжнаас гар өргөж суусан зорчигчид апп татуулах, бүртгүүлэх ЮУ Ч шаардахгүй — жолоочийн утас л таксиметр болно:

1. Зорчигч суугаад «Таван шар руу» гэнэ. Жолооч жолоочийн горимд **«Таксиметр»** том товч дарна — аялал шууд эхэлнэ. Хаяг оруулах **шаардлагагүй**, гэхдээ хүсвэл очих цэгээ зурагт тэмдэглэж болно.
2. Очих цэг тэмдэглэсэн бол: **урьдчилсан төсөв** харуулна — зорчигч багцаагаа мэдээд тохирно. Интернэттэй үед: нийтийн routing үйлчилгээгээр (OSRM/Valhalla-нийцтэй, endpoint жагсаалт тохиргоонд — OSM tile/relay-тэй ижил ангиллын нийтийн дэд бүтэц) жинхэнэ маршрутын зай → «≈ 14,000₮». Оффлайн үед автоматаар: шулуун зай × хотын ороо коэффициент (~1.35) × тариф, «ойролцоогоор» шошготой. Бодит төлбөр = таксиметрийн хэмжилтээр (эсвэл хоёулаа урьдчилсан дүнгээр тохирвол тэр нь).
3. Дэлгэцэд **том тоогоор**: бодогдож буй ₮ (профайлын км-тариф × явсан зай, газар дээр нь засаж болно), явсан км, хугацаа, маршрутын зурвас газрын зураг дээр; очих цэгтэй бол зайн үлдэгдэл. Зорчигчид харуулахад зориулагдсан тод харагдац.
4. **Бүрэн оффлайн ажиллана** — зөвхөн GPS; relay, сүлжээ огт хэрэггүй. Nostr event үүсгэхгүй.
5. Очоод «Дуусгах» → дүгнэлт дэлгэц: нийт ₮ / км / хугацаа + жолоочийн банкны QR яг тэнд. Зорчигч бэлнээр эсвэл QR уншуулаад буена.
6. Дүгнэлт дэлгэцийн доод хэсэгт жижигхэн: «Тахь — эзэнгүй такси» + апп татах QR — зорчигч бүр дараагийн хэрэглэгч болох боломж (§10-ын элсүүлэлтийн loop-ийн зорчигч-тал).
7. Аялал жолоочийн **локал журналд** бичигдэнэ (өдрийн орлого, км — жолоочийн өөрийн статистик). Нөгөө талын гарын үсэг байхгүй тул **нэр хүнд ҮҮСГЭХГҮЙ** (§9-ийн дүрэм зөрчигдөхгүй — self-attestation жингүй).

### 7.5 Цуцлалт ба маргаан
- Аль ч тал аялал эхлэхээс өмнө цуцалж болно (цуцлалтын DM).
- Төв шүүгч **байхгүй**: дуусаагүй/маргаантай аялал = хос баримтгүй = нэр хүнд өсөхгүй. Торгууль, нэхэмжлэл гэж байхгүй.
- Хэрэглэгч дурын npub-ийг блоклож болно (NIP-51) — дахиж харагдахгүй.

## 8. Төлбөр

- Апп мөнгөнд **хэзээ ч хүрэхгүй** — гүйлгээ хийхгүй, данс холбохгүй, custody байхгүй.
- Жолоочийн банкны QR зураг **зөвхөн утсан дээрээ локал** хадгалагдана; аялал дуусахад дэлгэцээрээ үзүүлнэ (Замын Унаа загвар) эсвэл хүсвэл тухайн зорчигчид шифрлэгдсэн DM-ээр илгээнэ. Нийтийн профайлд ХЭЗЭЭ Ч тавигдахгүй (дансны дугаар доксинг болохоос сэргийлнэ).
- Аппын үүрэг: тохирсон/бодогдсон дүнг хоёр талд ил харуулах — заавар өгөхөөс цааш оролцохгүй.

## 9. Нэр хүнд — хоёр талын, хуурамчлашгүй

Цөм механизм: **хос гарын үсэгтэй баримт**.

- Аялал бүрийн төгсгөлд хоёр тал тус бүрдээ kind 30177 баримт нийтэлнэ: ижил `trip_id`, бие биеийн npub, үнэлгээ.
- Баримт зөвхөн **хосоороо** (хоёр тал нэг trip_id дээр, бие биеэ заасан) жинтэй. Ганц талын баримт = жингүй.
- Өөрийгөө магтах Sybil-түүх үүсгэхэд хос бүрт хоёр identity, PoW, цаг хугацаа зарцуулна — үнэтэй.
- Клиент талын жинлэлт (web-of-trust): **олон өөр, өөрсдөө түүхтэй** counterparty-аас ирсэн баримт өндөр жинтэй; хоорондоо л магтсан бөөгнөрөл бага жинтэй. Тооцоолол бүрэн клиент дээр — сервер байхгүй.
- Харуулалт: аяллын тоо, дундаж үнэлгээ, сүүлийн үеийн идэвх, сэтгэгдлүүд. Жолооч зорчигчийн түүхийг мөн адил харна (хоёр тийш).

## 10. Unicorn-чанарын шаардлагууд

| Шаардлага | Хэмжүүр |
|---|---|
| Onboarding | Апп нээснээс эхний дуудлага хүртэл **< 60 секунд** (бүртгэлгүйн давуу тал мэдрэгдэх ёстой цэг) |
| Гудамжны элсүүлэлтийн loop | «Жолооч урих» дэлгэц: зорчигч ямар ч гудамжны таксинд QR үзүүлнэ → жолооч татаад **< 3 минутад** жолооч-горимд бэлэн. Аялал бүр = элсүүлэлтийн боломж |
| Аялал-хуваалцах вэб | Static HTML (GitHub Pages г.м., хэн ч mirror-лоно) — browser шууд relay-ээс уншина, түлхүүр URL fragment-д (сервер рүү явдаггүй). Апп-гүй хүн аяллыг харна + «Тахь тат» товч. Сервер биш — солигдох толь |
| Хэмжээ/хурд | APK < 40MB; хямд Android дээр cold start < 3 сек; сүлжээ тасрахад автомат relay дахин холболт |
| Дизайн | Монгол premium мэдрэмж (Дархай стандарт): бүрэн монгол UI, харанхуй/цайвар горим, тахь адууны brand identity |

## 11. Дэлхийд тархах чадвар (протоколын түвшинд)

- **PROTOCOL.md** — апп-аас тусдаа, хувилбартай спек: event схем, kind дугаар, урсгал, нууцлалын дүрэм. Өөр хөгжүүлэгч апп үзэхгүйгээр өөрийн клиент бичиж чадна.
- **Хот-агностик**: кодонд УБ hardcode 0. «Хотын багц» = config JSON (газрын зургийн төв, default relay санал, locale). Дархан ч, Бишкек ч = нэг config.
- **FORKING.md** — «өөрийн хотод асаах нь» нэг хуудас заавар.

## 12. Аппын бүтэц (Flutter)

```
takhi/
├── PROTOCOL.md           # takhi протоколын спек (хувилбартай)
├── FORKING.md
├── HELPER.md             # туслагч зангилаа (blind relay) асаах заавар — coturn + Nostr зарлал
├── packages/
│   └── takhi_protocol/   # цэвэр Dart: event схем, validation,
│                         # нэр хүндийн тооцоолол, Plus Code, PoW
└── app/                  # Flutter апп «Тахь»
    ├── identity/         # түлхүүр үүсгэх/сэргээх (NIP-06 seed)
    ├── nostr/            # relay pool, subscription, retry
    ├── ride/             # дуудлага/санал/тохироо state machine
    ├── meter/            # локал таксиметр (Замын Унаа горим, оффлайн, §7.4)
    ├── map/              # OSM (flutter_map), pin, Plus Code
    ├── call/             # P2P дуут яриа (flutter_webrtc + Nostr signaling)
    ├── payment/          # QR локал хадгалах/үзүүлэх
    ├── safety/           # аялал хуваалцах, SOS
    ├── i18n/             # mn + en
    └── ui/               # дэлгэцүүд (зорчигч/жолооч горим)
```

`takhi_protocol` бүрэн бие даасан, UI-гүй, 100% unit-тесттэй — протоколын лавлагаа хэрэгжүүлэлт нь энэ.

## 13. Мэдэгдэж буй хязгаарлалт ба эрсдэл (шударга жагсаалт)

| Эрсдэл | Байдал | Хариу |
|---|---|---|

| Хоосон сүлжээний cold start | Жолоочгүй бол зорчигч, зорчигчгүй бол жолооч ирэхгүй (QGO-ийн урвуу маркетплэйс сургамж) | Гудамжны QR loop (жолоочийг зорчигч өөрөө элсүүлдэг); эхний өдрүүдэд танилын тойргоос seed хийх — маркетинг биш, бодит аялал |

| Хууль | «Цахим платформд бүртгэлтэй жолооч» чөлөөлөлт төвгүй сүлжээнд хамаарах эсэх тодорхойгүй | Хойшлуулсан (шийдвэрийн бүртгэл §4). Аппад ил сануулга: хэрэглэгч эрсдэлээ өөрөө үүрнэ. 2-р шатанд эргэж харна |

## 14. MVP-д ОРОХГҮЙ (YAGNI)

Дайгдах · хот хооронд · цагаар хөлслөх · урьдчилсан захиалга · B2B · mn/en-ээс өөр хэл · крипто төлбөр · blockchain бэхлэлт · дуут захиалга · «баталгаажуулагч» давхарга · push notification сервер · оффлайн газрын зургийн багц · зохиогчийн TURN/туслагч сервер (сайн дурынхных дэмжигдэнэ, зохиогч өөрөө хэзээ ч ажиллуулахгүй) · Holepunch/Bare стекийг апп дотор шигтгэх (зарчмыг нь стандарт WebRTC+TURN-ээр авсан тул хэрэггүй). Бүгд протоколын өргөтгөлөөр дараагийн шатанд боломжтой.

## 16. Нээлттэй асуудлууд (спек батлагдсаны дараа шийднэ)

1. Dart Nostr сангийн эцсийн сонголт (ndk / dart_nostr / nostr_tools) — план бичих үед benchmark.
2. Default relay-үүдийн эцсийн жагсаалт — PoC туршилтаар.
3. Kind дугааруудын эцсийн утга + PoW-ийн хүндрэлийн зэрэг (difficulty) — PROTOCOL.md v0.1-д.
4. takhi.mn / takhi.org домэйн чөлөөтэй эсэх — шалгаад брэндэд бэхлэх (домэйн = сайхан-байвал, шаардлагагүй-хамаарал).
5. F-Droid нийтлэлийн шаардлага (reproducible build).
6. Нийтийн STUN серверүүдийн default жагсаалт + `flutter_webrtc`-ийн Nostr-signaling-тэй нийцэл — план бичих үед үнэлнэ.
7. Нийтийн routing endpoint-уудын default жагсаалт (OSRM demo / Valhalla / OpenRouteService) + ашиглалтын бодлогын шалгалт — tile сервертэй ижил зарчмаар.
